## 01 · 要做什么课题

### 1.1 · 拟定题目与实际应用

**建议开题题目：面向机器人抓取任务的世界模型动作后果排序方法研究。**

研究对象是仿真机械臂及移动操作机器人。以“抓住物体并在回合结束时满足任务要求”为目标，研究动作选择的可靠性。它可以对应货架取物、抓取与搬移等应用中的控制环节；当前实证范围是仿真抓取子任务，尚未覆盖工业仓储导航、运输和放置全流程。

| 研究定位 | 具体内容 |
|---|---|
| 现有基础 | TD-MPC2世界模型＋模型预测控制（MPC），从当前状态预测动作后果并搜索动作 |
| 要解决的问题 | 原始预测收益较高的动作，是否也更可能在完整回合结束时成功？如果排序不一致，能否纠正？ |
| 拟增加的方法 | 冻结现有TD-MPC2，训练一个小型结果评分器，在共同的4个首动作中重新排序 |
| 主要研究变量 | 同状态真实分支标签、世界模型的一步预测特征、终局结果监督 |
| 第一版输入 | 仿真状态向量与候选动作；视频用于展示。无需LLM API，无实机前提 |

世界模型本身主要预测“这个动作会导致什么状态和奖励”；规划器负责比较动作。本课题研究的是**世界模型预测怎样更有效地服务动作选择**，属于世界模型与机器人决策的交叉方向。

### 1.2 · 为什么值得研究

机器人可能已经抓住物体，却在后续移动或保持阶段不满足末步条件；也可能每个候选都不好。仅看模型训练损失、单步预测误差或一段成功视频，都不足以区分这两种情况。本研究首先验证是否存在“同一候选集合中有更好的动作，却没有被选中”的现象。

已有工作提供了基础，也限制了创新范围：TD-MPC2提供潜在空间规划；V-GPS已经研究价值引导的动作重排；2026年的TD-M(PC)²讨论规划与策略分布错配及价值高估；ContactGuard与Foresight展示了预测表示对失败监测的作用。**因此，“加一个评分网络”或“用世界模型预测失败”本身不能作为创新结论。** [TD-MPC2](https://www.tdmpc2.com/) · [V-GPS](https://proceedings.mlr.press/v270/nakamoto25a.html) · [TD-M(PC)²](https://proceedings.mlr.press/v331/lin26a.html) · [ContactGuard](https://arxiv.org/abs/2608.13438) · [Foresight](https://arxiv.org/abs/2606.23085)。

### 1.3 · 我们拟验证的三个贡献点

| 待验证贡献 | 具体做法 | 需要什么证据才成立 |
|---|---|---|
| 同状态动作后果监督 | 从同一个仿真状态出发，执行不同首动作，再由同一原控制器续跑；用真实终点结果训练相对排序 | 同数据下，优于普通状态—动作评分器；去除配对排序损失后效果下降 |
| 预测特征对决策的作用 | 将冻结世界模型的一步预测表示加入评分器，判断其是否有助于区分动作后果 | 在相同信息、数据、容量与候选预算下，优于去掉或打乱预测特征的对照 |
| 从离线排序到闭环任务完成 | 先检验单次换动作，再检验每一步持续重排；接触扩展时同时考虑成功和累计超限 | 离线排序改善能转化为完整回合的成功提升，并报告额外时延与接触代价 |

这里的“预测特征”是已有状态和动作的学习变换，不是额外看到了真实未来。创新性需由实验和进一步近邻比较共同支持，当前仅为研究假设。

**② Bootstrapped Model Predictive Control（BMPC）— ICLR 2025。** 问题：策略学习与价值估计不足限制复杂任务中的MPC。创新与方法：策略模仿MPC专家，策略再辅助MPC；结合模型TD学习和延迟重分析。评估：连续控制表现、数据效率、稳定性和训练时间；既有全文汇报覆盖DMC与HumanoidBench。局限与课题关系：如果候选本身没有好动作，应优先考虑先验／价值学习；冻结重排不能代替这类训练改进。当前仅精读，未复现BMPC。[论文](https://arxiv.org/abs/2503.18871) · [本地完整汇报](../BMPC论文汇报.html)。

**③ Steering Your Generalists: Improving Robotic Foundation Models via Value Guidance（V-GPS）— CoRL 2024，PMLR卷标2025。** 问题：通用机器人策略所用示范质量不一，部署动作仍可改善。创新与方法：用离线强化学习得到的价值函数重排策略候选，无需微调原策略。评估：多种策略、机器人平台和12项任务的控制成功表现。局限与课题关系：动作重排已有先例；我们的评分器必须与同数据普通critic比较，不能只与不使用额外标签的原版比较。[正式论文](https://proceedings.mlr.press/v270/nakamoto25a.html)。

**④ TD-M(PC)²: Improving Temporal Difference MPC Through Policy Constraint — L4DC 2026正式论文。** 问题：规划产生的数据分布与价值所评估策略之间不一致，导致高估。创新与方法：通过软约束策略更新改善价值学习。评估：连续控制性能与高维人形控制中的效果。局限与课题关系：已表明价值失配值得处理；我们的分支监督不等同于其策略约束，也不自动解决其TD学习问题。完整算法对照需要独立训练。[正式论文](https://proceedings.mlr.press/v331/lin26a.html)。

**⑤ ContactGuard: Pre-Contact Execution Monitoring with Action-Conditioned Latent World Models — 2026年8月预印本。** 问题：接触失败通常发现得太晚。创新与方法：动作条件潜在世界模型预测短期视觉后果，用轻量探针读出失败风险，在接触前中止执行。评估：实机失败检测、直接／动作扰乱消融及在线中止表现；详细指标见既有全文核验。局限与课题关系：中止信号不等于完成任务；借鉴冻结预测表示＋轻量读出，但必须验证候选重排的增量，不能宣称首次预测失败。[原文](https://arxiv.org/abs/2608.13438)。

**⑥ Foresight: Failure Detection for Long-Horizon Robotic Manipulation with Action-Conditioned World Model Latents — 2026年6月预印本。** 问题：长任务失败起点模糊、逐时刻标签难获取。创新与方法：用最终任务成败标签训练预测表示上的监测器，并以functional conformal prediction校准阈值。评估：LIBERO-Long、ManiSkill-Long、BEHAVIOR-1K及真实机械臂的失败监测。局限与课题关系：检测效果不等于闭环成功提升；本方案仅借鉴终局监督，不移植其时序检测器或校准保证。[原文](https://arxiv.org/abs/2606.23085)。

**⑦ Sparse Imagination for Efficient Visual World Model Planning — ICLR 2026正式论文。** 问题：视觉世界模型规划计算量大。创新与方法：随机分组注意力训练，减少预测时处理的视觉token。评估：控制表现与推理效率的权衡。局限与课题关系：当前状态MLP没有对应视觉token结构，首版不移植；它提示必须报告控制增益所付出的计算代价。[正式论文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/a750d52284ff70c6d6bab8072c392d74-Abstract-Conference.html)。

## 03 · 下一阶段怎么研究

### 3.1 · 任务安排：先验证机制，再扩展接触约束

本方案参考[下一阶段研究方案：世界模型动作后果排序](../refine-logs/FINAL_PROPOSAL.md)，保留E0→E1→E2及对照要求；结合本次最新核查，建议把执行顺序收敛为下表。原方案以HAB接触约束为主，但其旧基线已停止且未产生开发成功，现阶段优先使用已经跑通的任务。

| 优先级 | 任务与作用 | 进入条件 |
|---|---|---|
| 第一优先 | Meta-World V2 Pick-Place：检验“相同动作集合是否存在可纠正排序” | 复用冻结检查点；仿真与MPC重放审计通过 |
| 第二优先 | ManiSkill2 Pick Cube：做机械臂抓取迁移验证；Lift／Stack作为候选扩展 | E0存在改善空间；新任务先等原版基线有可评估结果，再按开发规则选定 |
| 条件扩展 | ManiSkill-HAB：检验累计接触限制与完整抓取成功 | 先解决或定位基础控制与候选覆盖问题；不能拿全失败候选训练排序器后期待成功 |
| 辅助材料 | DMC行走／奔跑：原方法复现与一般控制参考 | 不混入抓取成功率，不作为首版研究的必做主线 |

这两条抓取平台主线可以先验证**动作后果排序**；若HAB扩展未完成，论文题目和结论应保留抓取范围，不宣称已解决接触安全问题。任务选择按预先规定的开发诊断执行，保留未通过E0的任务记录。

### 3.2 · 方法流程：先产生真实标签，再学习选动作

<div class="flow-panel"><strong>数据采集／离线学习</strong><div class="flow"><div>恢复同一仿真状态<span>机器人位置、目标、控制器和随机状态一致</span></div><b>→</b><div>分别执行4个首动作<span>每条分支由原TD-MPC2续跑到终点</span></div><b>→</b><div>记录真实结果并训练<span>成功／失败，必要时记录接触超限</span></div></div></div>

<div class="flow-panel online"><strong>部署／闭环控制</strong><div class="flow"><div>原TD-MPC2产生候选<span>保留相同的原始搜索流程</span></div><b>→</b><div>小评分器对4个动作打分<span>使用状态、动作及一步预测表示</span></div><b>→</b><div>执行一个首动作<span>读取新状态，重新规划和排序</span></div></div></div>

**通俗解释：**给机器人同一个起点，先在仿真里试验4种走法，知道哪种更容易最终完成。再让小网络学会从当前信息判断这些走法，之后控制机器人时只执行选中的一个动作。部署时不能再偷看4个分支的真实未来结果。

原TD-MPC2仍搜索512条候选序列，其中含24条策略候选；从搜索结果中固定构造4个可执行首动作，包含原版选中动作、原分数最高动作及按固定规则取得的其他候选。新增评分器只在这4个动作中选择，不改变原6轮搜索过程。用原版抽样与同集合最高原分数两项参考，排除仅仅减少随机性带来的收益。

首版冻结编码、动力学、奖励、价值和策略先验，训练小型MLP。输入可写为`当前表示z、动作a、预测表示z′、剩余时间上下文`；其中`z′=f(z,a)`。Meta-World／ManiSkill2先预测原生终点成功，按成功分数排序。HAB扩展再加入累计接触量，核验类别互斥后预测成功／超限／其他失败，按`成功分数 − λ×超限分数`选择。

训练目标为**终局分类损失＋同状态候选的配对排序损失**。后者只比较实际结果有差异的动作，平局不造优劣标签。标签含义是“执行这个首动作后，由冻结原控制器继续控制的最终结果”；换成每步重排后会改变后续行为，因此单次干预与连续干预必须分别测试。

<details>
<summary>一个具体例子：末步稳定与接触扩展</summary>

机器人已抓住方块，候选A快速移向目标，候选B较平缓地接近目标。真实仿真分支可能显示：A早期到达目标但末步不再满足条件，B在末步成功。评分器应学习最终结果，而不是仅奖励“曾经到达”。这是待验证现象，不能将其写成现有Pick Cube失败回合的已查明原因。

若以后扩展HAB，评分器还可区分“更容易成功”与“更容易累计接触超限”。例如假设A成功分数0.20、超限分数0.75，B分别0.70和0.10；当λ=1时，两者得分−0.55和0.60，选择B。所有数字为教学假设，不是模型实测输出。评分不提供实机安全保证。

</details>

### 3.3 · 分阶段实施与交付

| 阶段 | 做什么 | 具体交付与进入下一阶段的门槛 |
|---|---|---|
| 准备：冻结协议与恢复核验 | 固定检查点、候选规则、初始条件分组；两次相同动作重放；核验环境、MPC缓存和随机数恢复 | 配置清单、恢复误差报告、失败条件分解；重复标签不稳定时先估计随机性 |
| E0：候选里有没有更好的动作 | 先做Meta-World 40个锚点×4分支；通过后在Pick Cube做同类诊断 | 每个平台至少8/40个锚点存在终点结果差异，至少4/40有替代动作优于原选择；输出同状态对比视频和候选改善空间 |
| E1：评分器能否学到有用排序 | 每基础种子400锚点×4分支；按来源回合／初始条件组划分240拟合、80模型选择、80锁定离线检查 | 学习曲线、预测表示／损失消融、同数据critic比较；先证明增益来源，再进入闭环 |
| E2：持续使用是否提高成功率 | 每方法先做50个开发回合；冻结后每任务、每域、每种子100回合；目标3个独立基础种子、4种方法 | 完整闭环成功率、失败分解、开销与视频；全部测试域报告，不只选正结果 |

E0门槛是节省算力的工程规则，不是显著性检验。原方案HAB接触相关门槛保留在条件扩展中。新增数据及其前缀重放、分支续跑均单独计入仿真预算，不能用公开数据集名称掩盖额外交互成本。

### 3.4 · 如何证明有效，而不是只看视频

| 必要比较 | 要回答的问题 |
|---|---|
| 原版TD-MPC2、共同4候选中原分数最高者 | 是否只是换了抽样方式？ |
| 同分支标签的状态—动作MLP、剩余回报critic | 是否仅因为多了一批有用数据或辅助价值网络？ |
| 完整评分器、去掉／打乱一步预测表示 | 世界模型的动力学特征到底有没有额外作用？ |
| 去配对损失、预测表示线性探针 | 相对监督是否必要，小网络复杂度是否必要？ |
| 单次换动作、每一步换动作 | 离线标签是否能支持实际闭环部署？ |

HAB扩展再加入简单力规则、保守Q以及去超限目标／累计量条件的消融。正式闭环先只保留4种方法：原版、同集合原分数最高者、按开发集预定规则选出的最强匹配对照、完整评分器。学习对照共享数据、可用上下文及调参预算；尽量匹配参数量。闭环进入不同状态后，匹配的是候选生成规则和预算，而不是声称动作内容完全相同。

**主指标：原生末步成功率。** 同时报告曾成功率及其与末步成功的差值、实际环境回报、候选排序正确率与选择损失，以及决策延迟p50／p95、模型调用次数、分支交互步数和GPU时间。接触扩展再报告原生累计超限率；普通Pick Cube没有本研究可冒称为官方的接触安全指标。

开发阶段沿用原方案的目标：成功率提高至少10个百分点，或在HAB扩展中超限相对降低至少30%且成功下降不超过5个百分点；端到端p95额外开销不超过15%。**这是筛选目标，不是已取得成绩或统计显著性标准。** Pick Cube若接近成功率上限，先做预定的E0诊断；不能看完锁定测试后为产生提升临时换任务或改阈值。报告每个训练种子、分组置信区间及全部负结果。

<details>
<summary>数据集、benchmark与泛化测试的具体约束</summary>

公开资源可用：[TD-MPC2代码／模型／回放数据](https://www.tdmpc2.com/)、[Meta-World环境](https://github.com/Farama-Foundation/Metaworld)、[ManiSkill2环境](https://github.com/haosulab/ManiSkill2)、[ManiSkill-HAB代码](https://github.com/arth-shukla/mshab)、[HAB任务、数据与检查点](https://arth-shukla.github.io/mshab/)。现有复现保留固定版本；不直接升级环境后混用旧结果。

这些平台提供任务、资产或轨迹，但公开演示通常没有“同一状态执行另外几个动作会怎样”的标签。本课题需要自行采集分支数据并公开配置、轨迹、标签与校验清单。原方法训练用交互回放；新评分器用离线分支监督，两者分开记账。

训练／开发／测试按完整来源回合和初始条件组划分；同一回合的多个时间片不能跨集合。已经反复看过的验证起点不再作为全新锁定测试。HAB扩展使用未接触布局；未能获得独立布局时只报告布局内范围。

原方案拟设3个评估域：未见布局／初始条件、执行增益0.6、增益0.6加1步延迟；开发增益1.0／0.8。迁移到Meta-World／ManiSkill2前要验证接口，只缩放适当运动通道，不随意改变夹爪语义。先冻结干预和划分，再查看测试表现；执行增益变化不叫摩擦扰动。

若要声称比原版更省数据，还须增加“原版＋等量额外在线交互”对照；与“同分支数据critic”分别控制交互数量和数据内容。尚未完成这一对照时，不主张整体数据效率领先。

</details>

### 3.5 · 资源、时间与失败时的调整

两张RTX A6000 48GB足以支撑当前状态输入的小模型验证；已有同配置原版训练是直接工程证据。新评分器目标不足50万参数，具体参数量和峰值显存以实现后测量为准。主要耗时预计在重复仿真与MPC分支续跑，而非评分器拟合，**显存有空余不等于可以无限增加并发**。

| 阶段安排（建议） | 预算与验收 |
|---|---|
| 先做准备＋E0，预留1—2天工程时间 | 每任务160个首动作分支；接触扩展如启动则先设4万HAB步上限。交付恢复核验、候选后果表与比较演示 |
| E0通过后做E1，预留数天采集与对照 | 每种子1,600条分支；评分器首轮拟合设3 GPUh上限，再依据测速分配最多12组参数搜索及各对照预算 |
| E1通过后安排E2 | 4方法×3种子×3域×100回合＝每任务3,600回合；200原生步／回合时为72万原生评估步，任务另计 |
| 完整研究排期 | 按1—2周起步安排验证迭代，再依实际吞吐、排队和基线补齐调整；不是结果收敛承诺 |

原方案按HAB约5.8控制步／秒估算单种子E1约15小时、E2约35小时，主体约130 GPU占用小时还包括新增基础种子。这些是**旧任务预算假设**，不能直接套给当前双卡并发的Meta-World／ManiSkill2。实施前先测速，并按已有可用种子重算，避免把已完成训练重复计费。Meta-World目前仅有1个训练种子，正式三种子研究还需补齐。

当前仓库安排为每卡3个原版任务流，至少保留12 GiB显存和15 GiB磁盘。新研究独立存放，待资源满足时调度；本报告不承诺双卡立即空闲，也不恢复旧HAB训练。原方案“仅用GPU1”的安排已由后续部署覆盖。

| 可能失败的环节 | 预先约定的处理 |
|---|---|
| 4个候选都不好，E0没有改善空间 | 停止扩大排序器训练，转向基础策略／候选覆盖；可再评估BMPC类机制 |
| 普通critic与完整方法同样好 | 不宣称世界模型预测特征创新；据实报告额外监督的作用 |
| 离线排序变好，但连续使用变差 | 分析后续策略改变造成的标签失配；补采必须作为单独版本与预算 |
| 仿真恢复不可靠或数据划分泄漏 | 先修复实验协议，不用不可信标签支持结论 |
| HAB始终没有可用基线 | 抓取机制课题仍可继续；收缩接触约束结论，不把该扩展写成已完成 |
