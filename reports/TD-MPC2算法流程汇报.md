# TD-MPC2：算法流程、训练与测试

**论文：** TD-MPC2: Scalable, Robust World Models for Continuous Control  
**作者：** Nicklas Hansen、Hao Su、Xiaolong Wang  
**发表：** ICLR 2024 · 解读依据：arXiv v2及官方实现 · 整理日期：2026年9月10日

**本次补充：** 第11节介绍104项连续控制任务与四类仿真平台；第12节区分环境、物体资产、示范数据及MT80/MT30；第13节详细说明评估步骤、指标和论文实验预算。

> 💡 汇报主线：机器人先在学到的模型中比较候选动作的后果，再进入环境执行；训练时利用真实反馈继续改进模型。世界模型负责预测，策略先验提出候选，MPC负责搜索和选择。

## 01 · 一页理解整个算法

TD-MPC2是一套基于模型的强化学习算法。它学习对控制有用的潜在表示，在这个表示空间中推演动作后果，无需把未来状态解码成图像或视频。

**两种“试一试”必须区分：**规划阶段是在神经网络里计算候选后果；选定后才在仿真环境或真实机器人上执行。原版MPC不会为每个候选都重置仿真、实际运行一遍。

## 02 · 五个网络模块，分别做什么

| 模块 | 输入 → 输出 | 它回答的问题 |
|---|---|---|
| 编码器 h | 观察 s → 潜在表示 z | 怎样把环境信息变成网络使用的表示？ |
| 潜在动力学 d | z、动作 a → 下一潜在表示 z′ | 执行这个动作，接下来会怎样？ |
| 奖励模型 R | z、a → 预测即时奖励 | 这一步可能获得多少奖励？ |
| 价值网络 Q | z、a → 预测长期回报 | 从这里开始，后续可能获得多少折扣奖励？ |
| 策略先验 p | z → 候选动作分布 | 什么动作值得优先尝试？ |

论文将策略先验也列入整体架构，因此图中会出现“预测动作”。但动作由策略先验提出，下一状态由动力学模型预测，两者职责不同。**Q值是回报估计，不是成功概率。**

依据：[原论文§3.1与Figure 3](https://arxiv.org/html/2310.16828v2#S3.SS1)、[官方网络代码](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/common/world_model.py)。

## 03 · 每一个控制步：如何规划动作

1. **编码当前观察。**用编码器获得当前潜在状态。
2. **生成候选动作序列。**从可调整的高斯分布中采样，并加入策略先验生成的序列；前一步规划结果可用于初始化本次搜索。
3. **预测候选后果。**动力学模型沿每个序列逐步推演，奖励模型预测各步奖励。
4. **估计总回报。**把短期预测奖励与规划窗口末端的价值估计结合。
5. **迭代改进采样。**根据高分候选及其权重更新采样分布，固定轮数地重复搜索。论文采用MPPI这种无需对动作求梯度的采样优化。
6. **执行首动作。**从最终搜索结果选出动作，只执行序列第一步；下一控制步重新观察和规划。

<div style="padding:18px 22px;background:#f8f5ec;border-left:4px solid #b8390e;border-radius:6px;font-size:18px;line-height:1.8"><strong>候选得分 ≈ 未来H步的折扣预测奖励 ＋ 第H步状态的折扣后续价值</strong><br><span style="font-size:15px;color:#555">概念式：G = Σ γᵏ R(zₖ,aₖ) + γᴴ Q(zᴴ,p(zᴴ))，其中k从0到H−1。实际实现还包含策略采样与Q集成等细节。</span></div>

这里的“末端”是**规划窗口的末端**，不是整项任务的结束。Q网络用来补充窗口之外的收益，所以短时域规划仍会考虑更远的未来；估计可能有误，并不保证找到最优动作。

依据：[原论文§3.2](https://arxiv.org/html/2310.16828v2#S3.SS2)、[固定版本官方规划代码：plan与_estimate_value](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/tdmpc2.py)。

## 04 · 训练：模型如何从不会到会

单任务从头训练时，网络初始没有任务能力。先用随机动作收集初始经验，之后交替进行环境交互、经验保存与网络更新。**不要求先有教师模型，也不要求先完成独立预训练阶段。**论文另外研究了多任务离线训练与新任务适配，不能与单任务从头在线训练混为一谈。

每次交互记录：**当前观察s、实际动作a、真实奖励r、下一观察s′**。数据进入经验回放池，训练时抽取连续片段。

| 更新内容 | 学习目标 | 如何理解 |
|---|---|---|
| 动力学与表示 | 预测的下一潜在表示接近真实下一观察的编码；目标分支停止梯度 | 让模型对动作后果的预测更一致 |
| 奖励预测 | 预测奖励接近环境给出的真实奖励 | 学会估计眼前收益 |
| 价值预测 | 学习“真实奖励＋折扣后的下一步目标价值” | 从经验中逐步估计更长远的收益 |
| 策略先验 | 提高提出动作的Q估计，并保留动作多样性 | 更快地提出值得搜索的候选 |

编码器、动力学、奖励和价值模块通过联合目标学习；策略先验按自己的目标更新。目标Q网络采用缓慢移动平均更新，减轻学习目标的波动。策略先验**不是默认通过模仿教师或照抄MPC动作训练的行为克隆模型**。

训练闭环：**交互 → 保存经验 → 抽样更新 → 用更新后的模型继续规划 → 继续交互。**

依据：[官方在线训练器](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/trainer/online_trainer.py)、[官方更新函数：update与update_pi](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/tdmpc2.py)。

## 05 · 为什么称为Scalable、Robust

| 关键设计 | 主要作用 |
|---|---|
| SimNorm | 对潜在表示分组归一化，帮助稳定训练 |
| 奖励与价值的分布式回归 | 在变换后的数值区间上学习软分类目标，适应不同奖励尺度 |
| Q网络集成与缓慢更新的目标网络 | 减轻价值估计偏差和训练波动 |
| 多任务嵌入与动作维度掩码 | 区分任务并支持不同观察、动作空间 |

这里的Robust主要对应算法训练和跨任务表现的稳健性，**不等于接触安全保证**。本文的重点是算法流程；这些机制是支撑它稳定运行和扩展的设计。依据：[原论文§3.1、§3.3及附录A](https://arxiv.org/html/2310.16828v2)。

## 06 · 测试时还做哪些事情

| 环节 | 训练阶段 | 常规评估阶段 |
|---|---|---|
| 读取观察、编码 | 是 | 是 |
| 候选采样、模型推演、MPC搜索 | 初始随机收集之后使用 | 是 |
| 在环境执行动作 | 是 | 是 |
| 使用经验进行梯度更新 | 是 | 否 |
| 网络参数 | 随训练变化 | 固定 |
| 主要输出 | 模型权重、学习曲线、交互数据 | 回报、成功率、评估轨迹 |

**参数固定不等于动作固定。**测试时MPC仍根据每一步的新观察重新计算动作。规划优化的是候选动作分布，而不是重新训练神经网络权重。

评估要采用任务原生标准。HAB的“最终成功”不能仅用“曾抓住物体”替代；多任务比较还要区分各环境的回报和成功定义。依据：[官方训练器中的eval](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/trainer/online_trainer.py)。

## 07 · 抓方块示例：预测、选择、执行

**以下是解释性示例，不是实验结果，也不表示潜在状态可以直接解码成这些物理描述。**

假设机械臂已经夹住方块，需要抬起并稳定保持：

1. 编码器整理当前机器人和物体的观察信息。
2. 策略先验提出向上抬的动作，规划器同时采样其他方向与幅度。
3. 世界模型计算不同动作序列的潜在后果与奖励预测。
4. 价值网络补充短期预测之后的收益，MPC据此进行搜索和选择。
5. 仿真器执行首动作，返回物体实际运动与真实奖励。
6. 训练时，用实际数据改进网络；测试时，只记录结果并继续规划。

物体会不会掉落，最终需要看环境中的实际执行。世界模型预测不是事实，也不是安全证明。

| 层次 | 原论文已有内容 | 我们的工作定位 |

| 基础算法 | 潜在动力学、奖励、Q、策略先验与MPC | 建立原方法基线 |

| 额外分支数据 | 原版规划使用神经网络推演 | 我们拟在数据采集阶段从同一仿真状态实际执行替代动作，获得结果标签 |

> 📝 新方案的研究问题：在相同候选与数据预算下，世界模型预测表示能否帮助选择更可能最终完成任务的动作？第一版冻结基础模型，主要改进候选评价与选择，不能直接声称改进了世界模型本体的训练方法。

## 09 · 汇报时可直接使用的讲解稿

TD-MPC2通过环境交互学习一个服务于控制的潜在世界模型。机器人每一步先读取当前观察，再产生多组候选动作序列。世界模型预测这些动作的短期后果与奖励，价值网络补充更远的收益，MPC经过多轮采样比较后选出动作，只执行第一步，再根据新观察重新规划。

训练时，真实交互数据进入经验回放池，用于更新动力学、奖励、价值和策略先验；测试时网络参数固定，但规划持续进行。我们希望在这套框架上研究更准确的动作后果评价，让机器人在接触约束下更可靠地完成任务，而不仅是获得较高的预测回报。

## 11 · 104项任务：四类仿真平台分别测什么

**连续控制**是指动作通常由连续数值组成，例如机械臂末端的位移、关节控制量或肌肉激活强度，而不是只在“左、右、停止”等几个离散按钮中选择。不同任务的动作维度、动力学、接触方式和奖励尺度不同，正是TD-MPC2要应对的差异。

<div style="padding:20px;border:1px solid #cbd9ec;border-radius:10px;background:#eef4fb;text-align:center;font-size:20px;line-height:1.8"><strong>104项任务 = DMControl 39 ＋ Meta-World 50 ＋ ManiSkill2 5 ＋ MyoSuite 10</strong><br><span style="font-size:15px">这是TD-MPC2论文选取的测试范围，不是四个平台全部功能或当前最新版本的任务总数。</span></div>

### DMControl：运动、平衡与基础控制

[DeepMind Control Suite（Tassa等，2018）](https://arxiv.org/abs/1801.00690)建立在MuJoCo上。典型任务包括倒立摆平衡、摆杆上摆、到达目标、Cheetah奔跑、Walker行走，以及Dog和Humanoid运动。它适合研究动力学学习、探索、不同动作维度与奖励稀疏程度下的控制能力。

TD-MPC2选取39项，其中包含作者加入的自定义任务，例如反向行走、跳跃和三连杆到达。**这些扩展需要使用论文配套代码，不能假设安装标准DMControl就全部具备。**状态输入包括关节位置、速度、身体姿态等，维度随任务变化；例如论文Dog任务为223维观测、38维动作。论文另做10项DMControl任务的视觉输入实验，不意味着全部104项都采用视觉输入。

**数据与资源：**平台首先提供可交互环境和模型资产，在线训练轨迹由算法自行产生；TD-MPC2还公开了包含DMControl任务的离线回放数据，见第12节。[官方代码](https://github.com/google-deepmind/dm_control)提供环境、MuJoCo接口、查看器及自定义任务工具。

### Meta-World：同一机械臂上的多种操作

[Meta-World（Yu等，2019）](https://arxiv.org/abs/1910.10897)面向多任务与元强化学习，围绕Sawyer机械臂设计操作任务，例如抓取放置、开关门、抽屉、按按钮、插接和工具操作。统一机器人结构便于研究技能共享与任务迁移。

TD-MPC2使用50项任务；其固定版本均为39维状态、4维动作。动作控制末端三个方向的移动和夹爪。**本项目使用的是V2 goal-observable接口，不能直接用当前V3结果替换。**平台的MT10/MT50与ML1/ML10/ML45等是不同的任务/训练测试协议，不是五个下载数据集；论文单任务实验也不等同于直接完成Meta-World的元学习协议。

**数据与资源：**[官方仓库](https://github.com/Farama-Foundation/Metaworld)提供环境与脚本策略等工具，可生成示范；TD-MPC2公开MT80中也有Meta-World交互数据。我们的Pick-Place V2基线从头交互训练，没有使用脚本专家示范。

### ManiSkill2：多物体、强接触的操作技能

[ManiSkill2（Gu等，2023）](https://arxiv.org/abs/2302.04659)以SAPIEN为基础，平台覆盖固定/移动底座、单/双臂、刚体/软体等操作，支持状态、RGB-D和点云等观测。原平台公开20类技能、2,000多个物体模型与400多万帧示范，适合模仿学习和物体泛化研究。**平台具有这些模态，不表示TD-MPC2本次接口使用了全部模态。**[官方项目与下载入口](https://maniskill2.github.io/)

TD-MPC2只选以下5项，并使用状态输入：

| 论文任务 | 要完成的动作 | 观测维度 | 动作维度 |
|---|---|---:|---:|
| Lift Cube | 抬起方块 | 42 | 4 |
| Pick Cube | 抓取并移到目标位置 | 51 | 4 |
| Pick YCB | 操作不同YCB物体 | 51 | 7 |
| Stack Cube | 堆叠方块 | 55 | 4 |
| Turn Faucet | 转动水龙头 | 40 | 7 |

本固定实现中4维控制是末端位置增量与夹爪，7维还包含姿态增量。Pick YCB涉及论文使用的74个YCB物体，但在104项统计中仍算**一个任务**，不是74个额外任务。YCB是物体资产集合，示范轨迹是另一类数据；二者不能混为一谈。原论文的ManiSkill2也不是我们后续采用的ManiSkill-HAB。

### MyoSuite：肌肉驱动的灵巧操作

[MyoSuite（Caggiano等，2022）](https://arxiv.org/abs/2205.13600)使用MuJoCo模拟生理结构较真实的肌肉骨骼系统。与直接给机械关节发动作不同，肌肉驱动带来多执行器协调和复杂接触问题；整个平台还支持疲劳、辅助装置等研究，但不能声称TD-MPC2评估了这些全部功能。

TD-MPC2选取手部到达、姿态匹配、转笔、持物和转钥匙五类任务，各设Easy与Hard，共10项。Easy采用固定目标，Hard采用随机目标；论文所选任务为39维动作、83至115维状态观测。它主要考察高维控制、灵巧接触和目标变化。

**数据与资源：**[官方仓库](https://github.com/MyoHub/myosuite)提供肌肉骨骼模型和环境；[TD-MPC2的MyoSuite模型目录](https://huggingface.co/nicklashansen/tdmpc2/tree/main/myosuite)提供相应权重入口。本次核查没有确认一个覆盖论文全部10项的统一官方离线轨迹包；需要数据时应查明具体任务版本，或在环境中自行采集，不能把模型权重当作数据集。

任务数量、论文接口维度与评估范围依据[TD-MPC2附录C、表2—6](https://arxiv.org/html/2310.16828v2#A3)；平台一般特征依据各自原论文与官方项目。原论文个别说明的维度口径可能与当前环境不同，实际复现实验需固定代码并记录运行时空间，避免跨版本套用。

## 12 · 有哪些公开数据：环境、示范和离线回放

**仿真环境不是静态数据集。**环境可执行动作并产生新观察、奖励及任务信号；数据集则是已经记录好的轨迹。下载公开数据适用于离线强化学习或模仿学习，从头在线强化学习通常自行收集经验。

| 数据/资源 | 具体包含什么 | 可用于什么 | 与当前实验的关系 |
|---|---|---|---|
| 环境交互轨迹 | 按回合组织的状态、动作、奖励、下一状态及任务/结束信息；实际字段依导出格式 | 在线RL回放、离线训练、失败分析 | 我们的Meta-World基线自行采集 |
| ManiSkill2示范 | 多种操作任务的成功示范；官方工具支持下载和回放 | 行为克隆、模仿学习、示范辅助RL | TD-MPC2单任务在线实验不因此自动使用它 |
| YCB等物体资产 | 几何、外观及仿真对象资源 | 搭建环境、物体变化测试 | 不等于带动作和奖励的训练轨迹 |
| TD-MPC2模型权重 | 已训练网络参数 | 推理、复核控制效果、新任务适配 | 我们本轮从随机权重开始 |

**TD-MPC2官方公开的两个主要离线数据集：**

| 数据集 | 任务组成 | 转移数量 | 数据性质 | 下载入口 |
|---|---|---:|---|---|
| MT80 | 30项DMControl＋50项Meta-World | 545M，约5.45亿 | 训练过程回放，包含随机到高水平的混合质量行为 | [MT80文件](https://huggingface.co/datasets/nicklashansen/tdmpc2/tree/main/mt80) |
| MT30 | 30项DMControl | 345M，约3.45亿 | 同类控制交互回放 | [MT30文件](https://huggingface.co/datasets/nicklashansen/tdmpc2/tree/main/mt30) |

数据来自240个单任务agent的回放，不是全是专家示范，也不是互联网视频。两者具有任务重叠，不能把转移数量相加后当作互不重叠的总数据量；它们也不是104项任务的完整公开轨迹合集。官方文件采用分块`.pt`存储，使用时按官方离线加载器核对格式、任务映射和回合边界。

来源：[作者数据卡](https://huggingface.co/datasets/nicklashansen/tdmpc2)、[官方任务集合与加载代码](https://github.com/nicklashansen/tdmpc2/tree/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2)。数据卡的大小描述与仓库显示的总占用不完全一致，因此这里不把某个下载GB数字作为固定承诺。

**三类实验要分开讲：**104项任务测试单任务在线学习能力；MT80/MT30测试一个模型在已有多任务数据上的学习与扩展；留出新任务后的在线微调测试迁移能力。我们的50万步Pick-Place只是第一类中的一项缩减预算复现。

## 13 · 论文怎样测试：流程、指标和统计方式

### 13.1 一次评估的具体步骤

1. **确定检查点与协议。**固定任务版本、观测和控制接口、动作重复次数、回合长度及训练预算。
2. **冻结网络参数。**切换评估模式，不执行优化器更新，不把评估轨迹加入训练回放；多任务模型还需输入对应任务标识。
3. **重置环境并完整执行。**每一步仍通过世界模型与MPC规划。2024固定实现按回合长度结束，不因为中途成功就提前停止。
4. **保存两类实际信号。**累加环境奖励；记录回合末步的任务成功标志。它们来自环境实际执行，不来自世界模型预测分数。
5. **重复多个回合。**固定官方配置默认每次10个评估回合；在线训练器默认每50,000次决策触发一次评估，并在回合边界执行。动作重复为2时对应约100,000原生环境步，具体配置可以不同。
6. **重复独立训练种子。**原论文主要单任务曲线报告3个训练种子的均值与95%置信区间。10个评估回合不能代替3次独立训练。

`eval_mode=True`关闭额外训练探索噪声，但MPPI候选采样和精英抽取仍可能随机，因此不能把评估称为完全确定性执行。独立测试还需要明确固定起点与随机种子，避免挑选成功视频代替完整评估。

流程直接核对：[2024固定版OnlineTrainer.eval](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/trainer/online_trainer.py)、[配置](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/config.yaml)、[多任务评估](https://github.com/nicklashansen/tdmpc2/blob/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/trainer/offline_trainer.py)。这里介绍2024论文协议，不能套用后来新增的episodic任务逻辑。

### 13.2 各平台的回合长度与主要指标

下表“回合配置”依次为：**原生步数 / 动作重复次数 / 决策次数**。

| 平台 | 回合配置 | 论文训练预算 | 主要任务指标 |
|---|---|---|---|
| DMControl | 1,000 / 2 / 500 | 通常4M；Humanoid与Dog等运动任务14M | 回合累计回报 |
| Meta-World | 200 / 2 / 100 | 2M | 末步成功率 |
| ManiSkill2 | 200 / 2 / 100 | 通常4M；Pick YCB为14M | 末步成功率 |
| MyoSuite | 100 / 1 / 100 | 2M | 末步成功率 |

M代表百万原生环境步。这些是论文表6的预算，不是我们已经跑完的实验数量。当前Meta-World单任务50万步是论文该平台200万步预算的四分之一，且只完成一个训练种子。原生环境步还不能直接换算成MuJoCo内部最细积分子步。

### 13.3 指标到底怎么计算

| 指标 | 计算方式 | 能说明什么、不能说明什么 |
|---|---|---|
| 平均回合回报 | 每个回合G=各步真实奖励之和；再对评估回合求平均 | 衡量任务奖励完成程度；不是成功概率，跨奖励尺度不能直接比较 |
| 末步成功率 | 最后一步成功的回合数 ÷ 评估回合数 ×100% | 反映完整回合结束时达成目标的比例；中途成功后掉落仍记失败 |
| 归一化综合分数 | 多任务实验将DMControl回报换到0—100尺度，与Meta-World百分制成功率按任务平均 | 方便汇总不同任务；不能解释为所有任务统一的成功概率 |
| 学习曲线与数据效率 | 在相同环境步数下比较回报/成功率，或比较达到固定目标所需步数 | 判断学习速度；不能用不同预算的终点强行比较 |
| 多种子均值与95%区间 | 对独立训练重复的任务表现进行汇总与不确定性报告 | 描述结果波动；我们单种子8/10尚不能提供同等证据 |
| 运行成本（辅助） | 训练耗时、GPU使用，以及必要时单步规划时延 | 衡量资源与部署成本；不替代任务效果指标 |

**例子A：**10个完整抓取回合中，8个最后一步成功，末步成功率是80%；若9个曾经成功，但其中1个后来掉落，曾成功率为90%，论文的主成功率仍是80%。本例仅解释口径，不是补充实验数据。

**例子B：**在按0—1每步奖励、1,000步回合评估的DMControl任务上，回报800可以按该范围归一化为80分；这不意味着“100次尝试有80次成功”。规划内部使用折扣价值，而日志中回合回报是环境奖励的累计，两者也要区分。

**成功条件来自各任务环境。**Meta-World读取`info['success']`；ManiSkill2读取相应任务的`success`；MyoSuite固定适配器把`info['solved']`映射为`success`。阈值与条件随任务变化，不存在一个“距离小于某个常数”适用于全部104项任务的统一标准。DMControl主要使用回报，不应凭空给它增加同名抓取成功率。

上述末步口径和回合参数依据[论文附录C](https://arxiv.org/html/2310.16828v2#A3)，跨任务分数依据[§4.1](https://arxiv.org/html/2310.16828v2#S4.SS1)；成功标志实现依据固定版本[环境适配代码](https://github.com/nicklashansen/tdmpc2/tree/57158282b46ebc5c329c5be9cfe2b0094126d1ca/tdmpc2/envs)。

### 13.4 汇报时怎样避免误读结果

**训练损失降低、模型预测奖励变高、视频看起来流畅，都不能单独证明任务成功。**应报告实际环境结果、完整回合数量、训练种子、预算和任务版本，并把最终检查点与中途最佳检查点分开。

我们的Meta-World基线是50万步、单种子、终点评估8/10；没有执行完整104项任务。HAB另外涉及累计接触力等任务条件，不能把这些指标声称为原论文四平台统一采用的标准。后续研究可以增加力超限率、曾成功与末步成功差距、p95规划时延等，但必须标为新增评价维度，并保留原生指标。
