# 复现说明

## 已验证运行方式

本轮使用 Linux + NVIDIA Vulkan/CUDA，Python 3.10.21、PyTorch 2.5.1+cu121、SAPIEN 3.0.3、Gymnasium 0.29.1。完整已安装包清单见 `upstream/environment-freeze.txt`；该清单包含旧环境的 editable 源码路径，不应直接用作新机器的 pip requirements。

仿真源码版本：

- ManiSkill HAB 兼容分支：`17121e3f96e3ee3ed0c03610b17f8bc2864617af`。
- MSHAB：`e9ff3d23496d38e4431c8d913e147ffa007f7f72`。
- TD-MPC2 模块：ManiSkill `62ff3a5896b4d5b4cf0ac4c8d79afe600c9404a3`，已放入 `vendor_tdmpc2/`，保留许可。

不要将两个 ManiSkill 版本同时作为仿真包安装。TD-MPC2 只使用复制出的算法模块。

在仓库根目录创建本机的 `local-settings.sh`（已被 Git 忽略）：

```bash
export HAB_DEP_ROOT=/absolute/path/to/validated/hab-installation
export HAB_PYTHON=/absolute/path/to/python3.10
```

依赖根目录需要有：

```text
third_party/ManiSkill/mani_skill/
third_party/mshab/mshab/
vendor_deps/                     # shortuuid==1.0.13 的额外安装位置
assets/data/scene_datasets/replica_cad_dataset/
assets/data/assets/mani_skill2_ycb/
assets/data/mshab_checkpoints/rl/tidy_house/pick/all/
```

`scripts/runtime.sh` 固定 GPU1，创建本仓库自己的缓存和临时目录。已验证环境的 SAPIEN 有一个仅修改 GPU 库缓存路径的补丁，使其遵守 `WM_SAPIEN_CACHE`；新机器默认 SAPIEN 未必识别此变量，必须记录并验证实际缓存路径，不能直接宣称环境等价。

```bash
# 控制入口预检：5 布局 ×（三方案 + 重复 SAC），每回合 30 步
bash scripts/local_server_entry.sh witness

# 正式配对开发实验：3 × 100 × 200 步
bash scripts/local_server_entry.sh run all

# 完整审计、图表、报告和对比 Demo
source local-settings.sh
source scripts/runtime.sh
python scripts/report_contact.py

# 状态训练入口：先预检，再短训
bash scripts/run_state.sh witness
bash scripts/run_state.sh pilot
```

输出目录已存在时入口会拒绝覆盖。复现实验应在新的工作目录运行，或显式实现新版本协议，不删除/覆盖旧结果以“重试到成功”。

## 新机器安装与数据

上述命令已在现有验证环境使用。下列流程提供新机器安装的依赖路线，尚未在第二台干净机器进行完整复现：

1. 创建独立 Python 3.10 虚拟环境，按已安装清单安装所需科学计算、PyTorch CUDA 12.1、SAPIEN、Gymnasium、tensordict、torchrl、OmegaConf、图像和视频依赖；不要安装清单中那条旧 ManiSkill editable 地址。
2. 克隆 ManiSkill 和 MSHAB，分别检出上面的固定提交，置于依赖根目录 `third_party/`；`PYTHONPATH` 由运行脚本设置。
3. 安装额外依赖 `shortuuid==1.0.13` 到依赖根目录 `vendor_deps/`，或该独立虚拟环境。
4. 配置 NVIDIA 驱动、Vulkan ICD 和 PhysX GPU 库；查看运行日志中的真实库路径，执行实际仿真预检。
5. 下载输入资产：

```bash
python scripts/fetch_assets.py --dependency-root /absolute/path/to/hab-installation
```

下载脚本固定 Hugging Face 提交，校验 ZIP 与 SAC 权重 SHA256，并防止 ZIP 越界解压。第三方资产使用原项目许可；实验 Release 保存的是本项目生成的全部实验数据，不重新打包上游场景库、Python 环境或缓存。

## 数据读取

- `initial_snapshot.pt`：本项目可信的初始模拟器状态、初始完整观测和 RNG 记录。使用 `torch.load(..., map_location='cpu', weights_only=False)` 读取；不要用此方式读取不可信 pickle。
- `trajectory.npz`：201 个状态观测、201 个两路最新深度帧、200 个 SAC 原始动作及实际执行动作。
- 深度堆叠重建：第 0 步完整三帧在初始快照中，之后依次将最新深度帧推入长度为 3 的队列，所得输入与记录时一致。
- `steps.jsonl`：每控制步的成功条件、力指标、动作缩放和耗时。
- `rollout.mp4`：20fps、201 帧，包含第 0 帧；不作为计算成功率的数据来源。
- 状态短训的 `train_*.npz`：201 个状态、200 个动作和奖励；`train_*.json` 保存对应训练布局、种子及逐步任务条件。

完整原始数据按实验归档在 GitHub Releases 中。下载后先校验清单，再解压至仓库根目录，HTML 中的本地视频链接即可使用。只克隆 Git 不会自动下载 Release 附件。

Git 文本统一使用 LF，防止 Windows 自动换行转换与原始报告校验冲突。`artifacts/source_snapshot/` 另存运行时源码的精确字节及原始/LF 归一化哈希；核验旧启动记录的原始代码 SHA 时应使用这份快照，第三方算法还可运行 `python scripts/verify_vendor.py` 核验固定上游版本。
