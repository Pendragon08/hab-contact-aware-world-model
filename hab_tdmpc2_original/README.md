# TD-MPC2 原方法迁移到 ManiSkill-HAB

[返回项目首页](../README.md) · [实验索引](../docs/实验与报告索引.md)。本页保留启动时的协议与估时；[2026-09-09 验证及启动证据](reports/验证与启动记录.md)不是实时状态，本仓库尚缺本轮正式完成与最终评估证据。

用户授权在 Meta-World 之外运行 HAB，两个正式实验按顺序使用 GPU1。GPU0 不占用并保留至少12 GiB空闲。

## 实验范围

本轮是 **TD-MPC2 原方法在 HAB 上的迁移基线**。TD-MPC2 原论文没有报告 HAB 成绩，不能称为复现原论文的 HAB 结果。采用与 Meta-World 原版实验相同的官方2024年源码，核心网络、损失、价值目标、策略先验、MPC、Buffer和随机探索/更新顺序不变。从随机权重开始，无教师示范、BC损失或风险模块。

| 项目 | 设定 |
|---|---|
| 任务 | `PickSubtaskTrain-v0`，Fetch 移动机械臂，TidyHouse Pick |
| 训练预算 | 500,000 环境控制步，action repeat=1 |
| 每回合 | 完整200步，忽略中途成功终止，末步检查全部成功条件 |
| 训练种子 | 1；按5个训练布局轮转，重置种子随回合增加 |
| 观测 | 原生42维状态+瞬时力/100+累计力/5000，共44维，不加时间特征 |
| 动作 | 11个有效通道，头部两个通道为0，与既有HAB适配约定一致 |
| 世界模型 | 官方5M配置，batch256，horizon3，官方折扣公式得到0.975 |
| 初始探索 | 1,000随机控制步，随后原版seed-buffer更新，再按原版在线更新 |
| 开发评估 | 0/10/20/30/40/50万步，各20回合，5个val布局，各检查点复用相同重置种子 |
| 成功条件 | 原生抓取、末端休止、机器人休止、静止、累计接触限制，五者同时满足 |

以上观测和动作约定属于环境接口适配，不是提出了新的TD-MPC2学习算法。通过验证布局评估迁移能力；20回合开发评估不是三种子统计或最终独立测试。算法有效性不能只看训练损失。

## 执行顺序

1. 短验证在GPU1上执行，仅允许与同一用户已知的Meta-World任务共享，并检查至少12 GiB剩余显存。
2. 独立执行者按 [EXECUTION.md](EXECUTION.md) 原样执行一次，通过后保存验证报告。
3. `launch_queue.sh` 提交一次性依赖队列，状态见 `artifacts/queue/status.json`。
4. 仅在Meta-World完成文件存在、记录50万环境步、GPU1占用<500MiB时启动HAB。等待超过24小时则退出并记录原因，不自动重启失败的Meta-World或占用他人的GPU。
5. HAB完成后自动在服务器归档数据；代码和报告放Git，全部原始数据后续发布GitHub Release并核验SHA256。

```bash
bash hab_tdmpc2_original/run.sh witness
# 独立验证报告成功后，仅提交一次
bash hab_tdmpc2_original/launch_queue.sh
```

不要修改已经运行的源码和配置，不覆盖旧结果目录。队列是在等待任务完成后执行一个已授权的训练，不是定时重复实验。

## 保存的证据

- `artifacts/seed1_500k/metrics.jsonl`：训练损失、梯度、回合奖励和末步/曾成功评估。
- `trajectories/train`、`trajectories/eval`：全部观测、动作、奖励及五项成功条件、接触量的逐步记录。
- `videos`：各检查点第一个完整评估回合。
- `models`、`final.pt`：各检查点和最终权重。
- `sources.json`、`resolved-config.yaml`：实际源码与配置。
- `complete.json`：仅在整个训练和末轮评估完成、源码一致性检查通过后出现。
