# Meta-World 抓取放置实验

将本项目的示范辅助 TD-MPC2 迁移到 Meta-World `pick-place-v3`：Sawyer 机械臂抓住桌上物体，将其移至目标位置。使用状态输入，不需要 LLM API、相机训练数据或真实机器人。

**当前为独立单任务先导实验。** Meta-World 3.1.1 / MuJoCo 3.3.0 / Gymnasium 1.1.1；不是原 TD-MPC2 论文的 V2 配置，不宣称复现原论文结果，也不是完整 MT1/MT50 基准。现有 ManiSkill 实验不受此依赖覆盖层影响。

## 代码、环境与数据

- [Meta-World 官方代码与任务](https://github.com/Farama-Foundation/Metaworld)
- [官方抓取放置脚本专家](https://github.com/Farama-Foundation/Metaworld/blob/master/metaworld/policies/sawyer_pick_place_v3_policy.py)
- [TD-MPC2 原始代码](https://github.com/nicklashansen/tdmpc2)
- [TD-MPC2 论文](https://arxiv.org/abs/2310.16828)
- 算法基础：本项目 `vendor_tdmpc2` 中已固定版本的 ManiSkill TD-MPC2 实现；`agent.py` 单独实现示范辅助与有限时域适配。
- 本次数据直接在公开仿真环境中生成。记录软件包 wheel 哈希、随机种子、初始物理状态、实际动作、专家标签、奖励与完整轨迹。无需另购数据集。
- `configs/env-spec.json` 声明运行环境；`configs/pick_place_v1.json` 固定实验方案。

## 算法与预算

1. 脚本专家采集 80 个起点、每次 500 步，共 40,000 步示范。脚本专家按规则输出动作，不是预训练世界模型。
2. 新建 5M 模型，进行 2,000 次联合预训练：状态预测一致性、奖励预测、行为回报监督的 Q 值、动作模仿。HAB 权重不加载。
3. 冻结当前策略，在训练起点中运行 20 次、共 10,000 步，记录它实际执行的动作及专家给出的纠正标签。
4. 使用示范与纠正数据，再做 3,000 次联合预训练。世界模型只学习实际执行的动作对应的转移；专家影子动作仅监督策略。归一化参数固定为最初 40,000 步示范统计。
5. 世界模型每次预测未来 3 步，MPC 比较 512 组候选动作、优化 6 轮、执行第一步。随后重新观察仿真状态并重新规划。
6. 在线交互 100,000 步，每步更新一次。已有完整在线轨迹后，动力学训练批次一半来自初始数据、一半来自在线数据。

输入为原生 39 维状态加时间进度，共 40 维；输出为末端 xyz 和夹爪，共 4 维。保留原生奖励，折扣 0.99，每条轨迹完整执行 500 步。成功后不提前结束；第 500 步不再引入未来价值。该有限时域与示范监督属于本项目适配，不是原论文原样配置。

训练和验证只使用 GPU1；GPU0 保留至少 12 GiB。GPU1 已有任务时拒绝启动新的 GPU 工作，不抢占其他进程。示范采集仅用 CPU。运行预算上限 12 小时，不自动重试或覆盖失败记录。

## 如何测试

训练起点索引 0–79；开发集 80–99；独立最终测试 100–119。种子为 1,500,000 加索引。检查随机化向量互不重复，直接策略与 MPC 的同一评估起点完全相同。

在在线步数 0、25,000、50,000、100,000 时，各用 20 个开发起点评估直接策略和 MPC。固定 100,000 步权重再用于 20 个最终测试起点；不根据最终测试选择权重。每组分别报告：

- 500 步内至少成功一次的比例：对应一次轨迹是否曾达到环境成功条件。
- 第 500 步仍满足成功条件的比例：检查任务完成后能否保持。
- 曾抓住物体的比例、累计奖励、动作计算耗时。

开发评估共 80,000 控制步，最终评估 20,000 步，分别计数。开发结果不能当作独立最终测试。单个训练种子与 20 次测试仅能给出初步证据；后续应增加训练种子和相同数据预算的基线。MPC 与直接策略对照用于检验规划是否有帮助，不能独自证明整个方法优于 TD-MPC2 原版。

每次评估保存所有轨迹与逐步指标，并为每种模式的第一个起点导出 MP4。MP4 是展示形式，数值结果来自实际仿真，不根据视频判断成功。

## 执行

在已有项目服务器上，先按 `setup.sh` 构建独立依赖覆盖层；**已安装的覆盖层不要重复安装**。`local-settings.sh` 由项目已有配置提供，只读解释器不修改。

```bash
bash metaworld_exp/run.sh collect
bash metaworld_exp/run.sh witness
# 独立验证通过，并记录 reports/agent_follows_doc.json 后：
bash metaworld_exp/run.sh run
```

工程验证执行 10 次离线更新、1 次混合回放在线更新，验证 5 个网络模块权重改变、回放一致性、终止目标与规划边界、权重保存读取以及 GPU 渲染。其 24 步短演示不用于成功率统计。

程序拒绝覆盖已有输出。结果位于 `metaworld_exp/artifacts/pick_place_v1/`；日志位于 `metaworld_exp/logs/`。代码与报告入 Git，轨迹、视频、权重通过 GitHub Release 配合 SHA256 保存；不上传环境、凭据或第三方依赖安装目录。

## 已发现的问题

首次重复种子检查失败：仅调用 `reset(seed)` 时，默认随机化路径仍使用全局 NumPy 随机数。现通过 `_freeze_rand_vec=False`、`seeded_rand_vec=True` 选择环境内的种子随机数生成器。修正后的两次完整专家轨迹在状态、动作、奖励上最大差异均为 0。原失败记录保留在 `artifacts/cpu_probe/`，修正版在 `artifacts/cpu_probe_seeded/`。这只是环境可重复性证据，尚不能代表训练成功。
