# 状态输入训练可行性验证

本轮为每算法 10,000 步的工程 pilot，尚未获得收敛或最终测试证据。训练使用 train，评估使用 val-development。

|算法|训练步|梯度更新|验证曾成功|验证结束成功|训练时间|PyTorch 峰值分配显存|
|---|---:|---:|---:|---:|---:|---:|
|tdmpc2|10000|9000|0/20|0/20|49.64 分钟|839.4 MiB|
|sac|10000|9000|0/20|0/20|32.73 分钟|756.0 MiB|

![训练损失](training.png)

两算法各 50 个训练回合和 20 个验证回合；初始状态向量在相同种子下逐一匹配。全部 18,000 条梯度更新记录有限，模型参数发生真实变化，检查点可读取。

PyTorch 峰值不包含 PhysX、渲染和 CUDA 上下文；整卡资源用量见资源采样日志。部分运行与接触对照共享 GPU1，时间反映实际运行条件，不能当作独占硬件吞吐。

TD-MPC2 采用上游 5M 档架构和规划器；本项目适配 HAB 状态接口、11 个有效动作通道和回合内回放。SAC 使用相同状态和交互预算，但网络规模不同。损失下降证明优化在进行，不能替代任务成功率。

时间上限按 continuing-task 设定自举；状态包含当前步比例，本 pilot 尚未比较有限时域终止处理的影响。

风险模块进入条件：先建立稳定完成任务的基线、充分训练预算及独立测试协议。本轮短训不足以声称风险规划有效，也不能据此否定世界模型。后续训练规模应根据这里测得的实际成本规划。

参数计数补充：原始 SAC 启动记录只对 actor 做参数变化哈希和计数。汇总表的模型参数量已根据保存的 actor、双 Q 和熵温度重新计算；原始启动记录保持不变。TD-MPC2 排除目标 Q 后计数。详细分项见 `parameter_audit.json`。

配置记录说明：TD-MPC2 原始 `resolved_config.yaml` 是上游算法初始化模板，其中未使用的环境名、训练步数、种子和评估数量仍为上游默认值。实际任务由 `HABState` 构造，预算与种子由 `state_pilot_v1.json` 决定；本轮真实运行 HAB Fetch Pick、10,000 步训练和 20 回合验证。原文件保留作审计，并新增 `effective_config.json` 与报告中的 `effective_configs.json` 明确本轮有效配置。该修正不改变训练轨迹、算法数值参数或结果。
