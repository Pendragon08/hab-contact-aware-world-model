# TD-MPC2 Walker Walk 论文方案复现

2026-09-10 用户要求先复现论文的 DMControl 任务，并查询GPU0。实测GPU0无计算进程、32MiB占用、48,519MiB空闲。按此次安排，本目录使用GPU0；此前HAB继续使用GPU1。GPU0仍保留至少12GiB空闲。

未指定DMControl子任务时，本轮选择论文中的 Walker Walk。正式预算不是50万步先导实验：3个种子（1/2/3），每种子400万原生环境步，即200万动作决策，动作重复2次，每回合500决策/1000环境步。使用24维原生状态和6维原生动作、原生奖励；每5万决策评估10回合。主指标原始回报0–1000，不使用DMControl接口中占位的success=0字段。

官方代码固定于 `57158282b46ebc5c329c5be9cfe2b0094126d1ca`，逐文件校验现有清单。官方5M模型、Adam、Buffer、学习损失、MPC、奖励尺度、2500决策探索和在线更新顺序均保持。折扣由官方公式得到0.99，规划horizon=3，batch=256。依据：[论文附录C/D](https://arxiv.org/html/2310.16828v2)。

## 复现边界

- 仿真依赖复用论文环境定义的 dm-control=1.0.8、MuJoCo=2.3.1、NumPy=1.23.5；Gym=0.21.0。新依赖只安装在本目录。
- Python=3.10.21、PyTorch=2.5.1+cu121、TorchRL/TensorDict=0.6.0来自现有环境，与历史环境不同；不能称逐位一致复现。
- 官方训练循环 `<=` 改为 `<`，避免额外一次动作；精确预算结束后显式执行最终评估。不改变学习顺序。
- 显式为Gym动作空间设置相同种子，避免独立的随机探索生成器不受全局种子控制。此可复现性修正已披露。
- 记录全部训练/评估状态、动作、奖励和物理状态；检查数值有限性。每100次更新写日志。每百万原生环境步保留权重，全部41轮评估均保存第一个回合视频和所有回合轨迹。
- 运行于GPU0，PyTorch分配上限为总显存65%；每回合检查显存和磁盘预留。没有修改GPU1运行文件。

## 执行与结果

独立验证见 [EXECUTION.md](EXECUTION.md)。正式启动由 `launch.sh` 创建专属screen；3个种子串行，每个完成后生成该种子的服务器归档和校验清单。任何失败停止队列，保留失败记录，不自动重试。

`artifacts/walker_walk_seed{1,2,3}_4m/` 保存结果；`logs/seed{1,2,3}.log` 保存日志；只有 `complete.json` 存在并满足预算才算完成。各种子完成后更新 `reports/summary.json` 与 `reports/当前结果.md`，3个种子全部完成后才报告三种子均值和置信区间。

作者原始结果CSV见 `reference/walker-walk.csv`。对应最终回报seed1=982.9、seed2=977.4、seed3=983.1；这些是论文参照，不是本轮成绩。与本轮比较同时报告逐种子和均值，不挑选最佳种子替代完整结果。
